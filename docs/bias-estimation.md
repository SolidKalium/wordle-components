# Estimating Player Biases from Past Board Color States

These are notes for an out-of-scope project idea. These notes are accepted to be rough.

Topic: Extending player biases and player move analysis into guessing how a specific player would play in response to a word. The idea would be to quantify the player's preferences, not just have an opaque model that predicts the player's moves. This could be extended slightly to search for words that are expected to be "easier" for one player and "harder" for another. A less explainable model might be better, since it might learn patterns that are subtler or more cognitively well-bounded than what a human would pick. Then trying to iterate on explainable models might be better developed based on that proxy. In any case, this would require a lot of work using relatively sparse data. I'd essentially be relying on users who publicly post their results frequently, unless NYT agreed to let me research the data.

- Players may evaluate multiple words before making a guess. We don't have access to this information. Some skipped words may because they break rules the player has (hard mode, they just don't feel like it uses enough new letters), they didn't think of it, or they decided a different word might split the remaining problem space better. Some players may try to limit themself to the words in the wordle list while others might not know which words are possible and use a much broader space.
  - «A choice model that assumes the player is selecting from a known set would misattribute retrieval effects to preference effects. The psycholinguistics literature on lexical access under constraint is probably more relevant than the econometrics framing for this piece.»
- «One thing that makes this more tractable than it might seem: the pattern observations at every turn are strong constraints. Each turn's pattern, combined with the known answer, typically reduces the candidate word set to single digits by turns 4–5. So the combinatorial explosion is concentrated in turns 1–2, where there are many possible guesses but also where player behavior is most stereotyped (people have favorite openers).»
- Models for the first turn or two can be done separately from the general guessing model.
- Re: estimating hidden guesses from visible board state: «the structure is simpler than a general graph — it's a layered DAG with 6 layers, maybe 10–100 nodes per layer after pattern-matching reduces candidates, and edges representing "this turn-N guess is consistent with and plausible given this turn-(N-1) guess." Viterbi or K-best Viterbi is the textbook algorithm for exactly this shape.» The tail possibilities for guess sequence doesn't necessarily need to be skipped for computational cost reasons, but more because it's noise.
  - My initial thought was that we might want to use a combination of forward and backward travel to validate that a guess is likely. Then I realized that for a small problem we can just run all paths forwards, or, since we only care about the top outputs, we can use Dijkstra.
  - On further analysis, the model for using Viterbi was one layer per turn, with the nodes representing guessed words. But guessing the same word on the same turn can still have distinct game states with regard to both "pure" knowledge and bias by the player. If we ignore the player bias with regard to how the current constraints were obtained, then we can still use Viterbi, but we lose a small amount of resolution. So the AI admits that Dijkstra is likely the superior algorithm here.
  - «Viterbi's value comes from the Markov property: if multiple paths arrive at the same state at time t, you only keep the best one because they're equivalent going forward. But here, "same word at turn 3" doesn't mean "same state at turn 3" — the full history matters. You'd have to define the state as (word, accumulated constraints) or equivalently the full guess sequence, at which point paths almost never merge and Viterbi's dynamic programming advantage collapses to exhaustive enumeration anyway.» «Dijkstra (or K-best path search) on the full sequence DAG is more honest about what's happening. Each path is a complete guess sequence, weighted by cumulative plausibility, and you want the K most probable complete paths. There's no state-collapsing shortcut because the full history is load-bearing.»
- First turn word choice can be estimated just by looking at wordle discussion forums, and used as a prior before any particular player's opening word is known.
- There may exist communities that share their actual guesses on each turn, which could give some priors about patterns, but only for a limited set of players. But it could be a useful testing set.
- «It's circular — you need the player model to reconstruct the guesses, and you need the guesses to train the player model. EM or variational approaches handle this kind of thing in principle, but the combinatorics of "dozens of candidate words per turn, six turns, correlated through belief state" make the joint space large.»
- «hard mode players are much more constrained. Each guess must be consistent with all previous feedback, so the candidate set at each turn shrinks fast. A turn-5 guess in hard mode with 4 greens might have only 1–3 possible words. But players not in hard mode could guess anything valid, making reconstruction far more ambiguous.»
- A simple model will apply weights to properties for each word and then use a linear combination of those weights using player preferences. Note that the weights for a word aren't all static and some depend on the previously learned information.
  - Even features that seem like they should be static may still interact with state. For instance, word frequency/commonness might predict guesses some of the time, but in a constrained space, the word might become harder to guess, such as due to phonetic assumptions or similar.
    - Notably, a friend playing a rhyming game assumed that "close" needed rhymes from "to close the door" and only when I asked it accepted rhymes in the sense of "a friend is close by" did they try that.
  - «The model is something like a linear scoring function over those features, and the per-user weights capture "this player overweights familiar-sounding words and underweights information gain." This is basically a conditional logit / discrete choice model, which is well-studied in econometrics for exactly this kind of "person chooses one option from a set" problem. The econometrics literature calls your problem "choice modeling with large choice sets" and has techniques for it.»
  - An LP-inspired substitution-by-edge-traversal algorithm may work well for «"search over model architectures" version of the problem — where you're not just selecting features but considering interactions and nonlinearities. For the linear feature selection version, simpler tools work: stepwise addition with cross-validated held-out game prediction, or L1 regularization (lasso) which does the selection automatically by zeroing out weak features. The lasso approach is nice because it handles correlated features gracefully — if positional letter frequency and bigram frequency are capturing similar signal, it'll keep one and drop the other rather than splitting weight between them unstably.»
  - To add an "attention" mechanism, one can add *feature engineering* by adding x, y, and x & y features. Many of these will be noise and their quantity is combinatoric.
  - An alternative is to use a neural network, but costs explainability, network weights shape what the user-bias weights actually mean.
    - «This is sometimes called a *deep choice model* or *neural conditional logit*.»
      - user + state + word features → scalar score, normalized across candidates
    - The key use is likely as an upperbound on a more explainable model.
  - user + state → probability over all words. This treats the words as atomic labels and doesn't support the named properties approach.
  - «*Premix state + word, then add user*. This produces a representation of "how does this word relate to this game state" — things like "this word would eliminate 80% of remaining candidates" or "this word reuses three already-confirmed letters." These are objective, player-independent properties of the (word, state) pair. Then user weights modulate which of those properties matter. This is the most interpretable split: the first network learns game-relevant word properties, the second learns player preferences over those properties. You can inspect the intermediate representation and ask "what does the network think is strategically relevant about this word in this state" independently of any player.»
    - if the bottleneck between the two networks «compresses to 3–4 values, [that would mean that] players differ along a small number of strategic axes»
  - «*Premix user + state, then add word*. This produces a representation of "what is this player looking for right now" — a player-and-context-specific query vector. Then word features are scored against that query. This is essentially an attention mechanism: the player's current mental state determines what word properties get weighted. It's less interpretable at the intermediate layer (what does "player A in this state" mean as a vector?) but more natural for capturing "this player cares about vowel coverage early but switches to positional precision late."»
  - «*Premix user + word, then add state*. This would capture "player A's baseline affinity for this word regardless of context." Less useful — the whole point is that word value is state-dependent.»
  - «On the subnetwork architecture — you're essentially proposing learned feature extractors that replace hand-engineered features. Instead of computing "bigram typicality" as a single scalar using some formula you chose, you feed the raw bigram identity (or even the raw character pairs) into a small network and let it learn what matters. The advantage is that you don't have to decide whether initial "ch" and final "ch" are the same — the network discovers whether they should be, and you can inspect whether they are by comparing the learned representations. The binary/boolean framing is interesting because it forces each subnetwork to make discrete claims about the word rather than hiding behind continuous values whose scale might be absorbing work that should belong to the downstream layers.» My concern was that assigning non-binary properties to a word might be done poorly, so making the network decide the shape of the features based on detailed binary propositions preserves high signal. I suggested that some properties are "true binary" meaning that they aren't coerced to binary but that their inherent structure is binary. It allows testing the number of variables and their precisions that are minimums to maintain model quality. Effectively measuring the "bandwidth" of the data.
    - One drawback is that these subnetworks are going to be related to a specific word length. «Whether it actually scales depends on whether the subnetwork learned the concept or just memorized a lookup table for 5-letter patterns, which is the perennial question with small networks on small vocabularies. You'd only know by testing on a different word length,» which depends on data availability to test. «For longer variants it becomes a dominant factor — the player's morphological parser is doing most of the candidate generation work, and modeling that parser is closer to computational psycholinguistics than to ML feature engineering.»
- Each turn in the game can usually be treated as independent of other turns in the same game, just with varying levels of constraints on the guess. This does assume we know the words with reasonable certainty.
- Explainability is still frontier research, but especially for very large models. Asking "if I define the whole model this way and the only thing that can be trained is the input weights for a user, how well does that capture the player's behavior" seems like a relatively easy version of the problem, with the real issue being closer to how to traverse the space of potential fixed models.
  - Generally, we can use a large space of metrics, then remove dimensions that don't contribute much: their impact tends to be 0 for most players or it's the same for most players.
  - "fixed model architecture, train only per-user weights" should be tractable.
- «residual analysis in choice models is hard precisely because the "direction" of the error isn't obvious.» «You know the model was surprised, but the surprise doesn't point anywhere in feature space.»
  - «The productive version of this is probably: compute, for each game state, the model's predicted probability of the word the player actually chose. Situations where that probability is consistently low across multiple players are where the model is systematically wrong. Then you look at what those game states have in common — not what the chosen words have in common, but what the decision context looks like. Maybe the model consistently underpredicts in states where there are exactly 2 remaining vowel positions to fill. That's a missing interaction feature, not a missing word property.»
  - «the practical advice is: don't try to locate missing features from residuals alone.Instead, maintain a backlog of hypothesized features (your bias catalog is already this), and when you add one, check whether it reduces the systematic prediction failures you identified. The residual analysis tells you where the model is wrong; your domain intuition about human cognition tells you what to try; the fit improvement tells you whether it helped. The three steps use different tools and trying to collapse them into one automated process is where people get stuck.»
- Looking for words where different players are expected to perform differently requires having extracted meaningful signal, not just having a model that "fits"
- It would be hilarious if, from just public colored-square boards, we could (1) identify which words are considered sensitive in some dimension and (2) in at least some cases estimate with reasonable certainty that someone favors, disfavors, or has no usage bias for those words.
- Terminology
  - Each guess we can't see is a *hidden variable*
  - The problem is *inference over a latent sequence*
  - The words a player considered and rejected form an invisible *negative class*
    - «Techniques for learning from positive-only data exist (*one-class SVMs*, *PU learning*) but they need strong priors about the negative distribution, which loops back to [the] bias model.»
    - A rejected word can still contribute anchor or other biases. This impact would likely be even larger for longer word lengths.
    - These can be partially visible: «If a player consistently finds root + suffix words quickly but struggles with monomorphemic words of the same frequency, you can infer that their retrieval mechanism is morphologically structured even without seeing their rejected candidates. The pattern of difficulty across word types reveals the retrieval architecture. Which is a more tractable version of your original question — you don't need to observe what they considered, just observe that certain word properties systematically predict how long they take or whether they fail.»

## Separating Problem Parts
With access to the NYT corpus, the problem can be split into two halves.

- Latent inference: Given a certain board state, how well can we guess the word sequence? The degree to which this includes player-specific knowledge would need to be carefully defined.
- Cognitive linguistics: Given a player's history of guess sequences, how well can we predict their moves in a new game?
- Combined: This topic would need to be defined carefully. One question could be about what we can discover without the intermediate corpus or results derived from it, and how they compare to the informed versions. This could try to assign error source to one problem or the other.
  - «tuning reconstruction using knowledge of "what kinds of words people tend to guess" and then testing "do people guess these kinds of words" launders your prior into your result»

## Problem Difficulty Estimation
Situations where this question might be asked and answered

- Master's thesis, empirical not frontier. "Do per-user feature weights in a conditional choice model explain meaningful variance in Wordle play?" «Treat the latent guess reconstruction as a solved subproblem (use EM, accept noisy estimates, move on).» «The modeling framework exists (conditional logit), the feature engineering is novel but bounded (your bias catalog), and the evaluation is clean (held-out game prediction accuracy). A strong MS student in stats or computational cognitive science could do it in a year.»
- PhD thesis chapter: «Joint inference over hidden guess sequences while simultaneously learning the player model that governs those sequences is a genuine methodological challenge. It's not unprecedented — hidden Markov models and their descendants do this kind of thing — but the state space here is unusual: large discrete choice sets that shrink dynamically based on the hidden sequence itself. Getting that to converge reliably, proving it recovers known behavior in synthetic data, and characterizing when the posterior over guess sequences is too diffuse to learn from — that's closer to a PhD chapter. Not a full dissertation, but a substantial methodological contribution paired with the empirical application.»
- Semester-long team project in graduate ML or computational social science. Core modeling: observed guesses, fixed feature set, fit per-user weights. Skipping latent reconstruction or it could be provided.
- Grant-funded graduate cognitive science project: "what does the model structure tell us about human lexical retrieval under constraint?" Or possibly as the instrumentation for a PhD dissertation in this topic, where Wordle and its analysis are not the main point.
